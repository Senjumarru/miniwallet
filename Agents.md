# Правила работы над miniwallet

## Проект
Go 1.27, платёжное ядро: SQLite, HTTP API, вебхуки провайдера, сверка.
Деньги только int64 в минимальных единицах (тиыны). Провайдер пока fake:
не придумывай его API, где данных нет, ставь TODO(docs).

## Незыблемые инварианты (нарушение = P0)
1. Сумма и валюта платежа берутся из заказа в БД, никогда от клиента.
2. Пользователь определяется только из проверенного JWT (HS256, exp обязателен).
   X-User-ID и user_id в теле игнорируются.
3. На заказ не более одного pending и не более одного succeeded платежа.
   Это гарантируют индексы БД, а не проверки в коде.
4. Идемпотентность: арбитр это уникальный индекс. Схема "проверил, потом
   вставил" запрещена.
5. В failed платёж переводится только при однозначном отказе провайдера
   (4xx кроме 429). Таймаут, 5xx, 404, разрыв соединения = исход неизвестен:
   платёж остаётся pending, решает сверка по ключу pay-<payment.ID>.
6. Вебхук: лимит тела, сырые байты до JSON, hmac.Equal, окно timestamp,
   дедупликация и обработка в одной транзакции. Инциденты (несовпадение суммы
   и т.п.) фиксируются коммитом, ошибка возвращается после коммита.
7. Секреты без значений по умолчанию: отказ запуска при пустых, коротких
   (<32 байт), dev-значениях или одинаковых секретах. Небезопасный режим только
   при явном APP_ENV=dev.
8. ErrUniqueViolation только для UNIQUE/PRIMARYKEY (белый список). Прочие
   ошибки БД это внутренние ошибки, а не "заказ занят".
9. Клиенту не отдаются внутренние ошибки. В логах нет секретов, подписей, тел
   вебхуков и персональных данных.
10. Время только UTC и только через Clock.

## Как работать
- Одна задача = один коммит. Сначала план (3-7 пунктов, список файлов), ничего
  не расширяй "заодно".
- Сначала тест, который падает (покажи падение), затем исправление.
- Не ослабляй и не удаляй существующие тесты. Если тест закрепляет
  неправильное поведение, замени его и объясни почему.
- Не знаешь, значит пиши "НЕ ПРОВЕРЕНО". Запрещены слова "всё работает",
  "100%", "production-ready" без показанного вывода команд.
- Вывод команд приводи реальный и полный, без "...".
- Ветки с ошибками считаются непокрытыми, пока мутация не доказала, что тест
  падает при поломке.
- Запрещено: игнорирование ошибок через `_ =` без комментария зачем, panic в
  библиотечном коде, глобальное состояние, time.Now() в бизнес-логике,
  `if false &&`, закомментированный код, новые зависимости без причины.
- Ошибки оборачивай через %w и проверяй errors.Is/As. Контекст пробрасывай.
  У каждой горутины есть условие завершения. Ресурсы закрывай через defer.
